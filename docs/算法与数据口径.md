# 算法与数据口径

本文说明监控如何取得百分比、关联本机 token、计算金额，以及哪些情况会保守拒绝估算。

### GPT-6.1 Terra（2026-10-27）

内置 `gpt-6.1-terra` 的 Standard API 输入/缓存读/输出价格为每百万 token `$1/$0.05/$5`；超过 272K 输入 token 的官方长上下文对比价格为 `$2/$0.10/$7.50`，基础口径仍不加长上下文附加费。30 分钟 API 缓存写价格档位为 `$1.25/$2.50`，不改变用户已有缓存写配置。来源：[官方价格表](https://developers.openai.com/api/docs/pricing)、[模型说明](https://developers.openai.com/api/docs/models/gpt-6.1-terra)。

按现有套餐额度口径，Standard 为 1 倍、Fast 为 2.5 倍，不套用 API-key 或购买 credits 的 2 倍 Fast 计费。来源：[Codex Speed](https://learn.chatgpt.com/docs/agent-configuration/speed)。旧设置只补齐缺失新模型，已有同名自定义价格不覆盖；升级后已有明细优先离线重算，日志补录继续独立进行。

## 数据来源

### 权威额度百分比

程序启动独立的 `codex app-server --listen stdio://`，通过只读方法 `account/rateLimits/read` 查询当前登录账户的额度窗口，并监听 `account/rateLimits/updated`。

独立 App Server 不保证收到其他 Codex 进程的全部通知，因此通知用于尽快刷新，低频轮询仍是安全网。默认轮询间隔为 60 秒，最低可设为 10 秒。

### 本机 token

程序增量读取配置的 `.codex\sessions` 下 rollout JSONL，只消费与真实模型响应关联的 `token_count`。历史回填还会自动发现同级 `.codex\archived_sessions`，并按 rollout 文件名合并活动与归档副本：

- 输入 token；
- 缓存读取 token；
- 缓存写入 token；
- 输出 token；
- 推理输出 token。

工具事件、心跳、重复累计状态和孤立遥测不会重复计价。Desktop、VS Code 和侧栏任务只要写入同一 sessions 根目录，都会纳入候选。

## 触发与历史重放

### 改价后的重算

样本保存逐响应的模型、服务层级、输入/缓存读写/输出 token，不保存对话正文。保留逐响应长度是为了在长上下文阈值修改后正确重新分类，不能将整个区间的 token 合计用于阈值判断。

保存价格时优先从持久化明细离线重算，不需要网络或原始 rollout。旧版样本没有明细，首次升级会从保留期日志补录：先当前周，再旧窗口；状态栏显示阶段和文件进度。改价过程中再次保存会取消旧扫描，并在退出后立即处理最新查询请求。只有缺失明细补录需要取得有效额度快照；现有明细的改价计算不依赖额度查询。

等待期间保留同一旧价格版本的完整曲线，明确标记“旧价格”，新结果完成后切换，不将两种价格混合回归。不能补录的旧记录保留，重算覆盖数、缺明细数和计价错误明确显示；扫描结束不等于所有历史都已成功重算。重复改价或恢复相同价格不会重复插入同一区间的目标版本。

1. 首次读取建立当前周窗口和百分比基线。
2. 百分比未变化时，不执行普通全量日志扫描。
3. 百分比变化时，按持久化字节游标读取新增 JSONL。
4. 价格版本、重放算法或当前权威时间线变化时，从当前周仍存在的日志重建当前窗口。
5. 待日志或待层级文件被补写后，下一轮查询会重新尝试归因。
6. 断网恢复后首次取得新百分比时，程序会以权威检查点重新切分区间，并按当前重放算法追溯本周日志。
7. 首次升级到多窗口算法、价格变化、历史保留天数变化或活动/归档根布局变化时，后台一次性扫描保留期内旧日志，按每个稳定 `resets_at` 簇分别重建旧窗口。

历史重放不会修改实时增量游标；同一检查点重复执行保持幂等。

### 原子保存与短时文件占用

状态先流式写入同目录临时文件并强制落盘，再原子替换正式文件，上一代保存在 `.bak`。Windows 共享冲突、锁定和 `ERROR_UNABLE_TO_REMOVE_REPLACED (1175)` 只在临时文件与正式文件仍存在时重试，最多额外五次，异步等待分别为 25/50/100/200/400 ms；等待期间不阻塞后台状态保存的 UI 消息循环。

恢复后运行日志保留首次原始异常；持续失败仍抛出实际异常，附带尝试次数及首次失败信息，保留临时文件供检查，不把失败标记为保存成功。不对权限、磁盘或可能部分提交的 1176/1177 错误盲目重试，也不先删除旧文件或改用非原子覆盖。错误码后的文件状态依据 [Microsoft ReplaceFile 文档](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew)。

rollout 文件使用 64 KiB 缓冲流式逐行读取；即使单个 JSONL 达到数百 MB，也不会同时保留整文件字节、完整文本和行数组。文件末尾尚未换行的半条记录不会解析，字节游标停在上一条完整记录后，等待后续写入补齐。

旧窗口只有在同一重置簇内至少出现两个百分比严格递增的观察点时才可计算。候选观察时间必须位于其声明窗口内；下一个重置簇首次出现后，前一窗口立即截断，从而排除重置后仍被旧会话重复写出的陈旧快照。活动与归档中同名 rollout 只读取文件更完整的一份，避免重复计价。

## 金额计算

### 基础计费不依赖长上下文对比（1.10.13）

关闭长上下文对比意味着继续按基础 Standard API 档位计算，不因输入超过 272K 就停止计费。对比是独立的可选口径：即使对比档位留空，基础模型、层级和所需基础 token 价格明确时，仍生成基础样本。缺少基础价格或基础缓存写价格、未知层级等情况仍报告错误，不猜测费用。

`PricingResult.Success` 表示基础计价成功；对比用 `OfficialLongContextAvailable` 单独标记，并保留 `OfficialLongContextIssue`。实时扫描、待采样累计、历史响应及额度样本继续传递该标记。区间任一响应缺少对比价格时，整个区间的对比不可用，不能只合计其余响应的金额；基础区间照常计算。

持久化数值字段在对比不可用时的零值不是零费用，读取者必须先检查可用标记。界面显示 `—`，对比图及回归明确排除该区间；开启对比时提示缺价数量。旧的已知双口径样本默认可用，升级后的新价格版本从保留的逐响应明细和日志回补；不覆盖用户留空的价格配置。

每个有效百分比区间分别计算两种 Standard API 等价成本：

```text
基础区间成本
= 公开 Standard API 常规价格计算的 token 成本
× ChatGPT 额度倍率

官方长上下文区间成本
= 输入不超过 272K 时的基础成本
  或输入超过 272K 时：输入类 token 2×、输出 token 1.5×
× ChatGPT 额度倍率
```

再按额度百分比变化外推：

```text
Standard API 等价周额度 USD
= 区间成本 USD × 100 / 周额度已用百分比增量
```

“Standard API 等价周额度”是界面默认口径；“官方 >272K 加价”严格应用公开 API 规则，不会简化成整笔金额统一翻倍。第二口径的事实仍会随样本保存，但只有用户在“设置 → 估算”中显式启用后才进入界面、托盘和快速详情对比。

“设置 → 模型价格”允许逐模型修改短、长上下文的未缓存输入、缓存读取、缓存写入和输出单价，以及长上下文阈值。自定义价格保存后会形成独立价格版本，并自动触发当前周和图表保留期历史重算；旧版本样本保留为归档但不会与新价格混入同一回归。“恢复内置价格”只重置价格编辑值，保存后重新使用程序内置版本。

## 跨重置日志与覆盖保护

文件修改时间可能停留在会话创建时，但内部仍有新响应，因此不能用 `LastWriteTimeUtc` 排除新周日志。读取器先按完整 JSONL 记录建立事件时间索引，后续对相同文件复用索引、仅索引新增字节；截短、替换或同长度修改会重建。修改时间只辅助识别文件变化，不决定事件所属周。窗口相关文件仍重读完整模型上下文，保留 Fast/Standard 的实际切换证据。索引仅驻内存，不保存对话正文；重启后首次扫描需要重新建立。

当前周和归档重放按相交百分比区间整体合并。同一或更宽观察时间范围内，若响应数量、输入/输出量或已有完整逐响应用量减少，拒绝替换并保留旧记录；拒绝数持续显示在状态栏。部分区间拆分不能删掉未重建的百分比；合法较早首次观察边界、用量完整但价格下降不受阻止。未知层级仍报告为未归因，保留旧记录不代表已确认旧值正确。

## 速度监测口径

额度与速度图的下拉框设置初始图表范围及独立表格范围。滚轮围绕鼠标时间点缩放、左键拖动平移，实际可见窗口决定图表、回归及速度指标；表格仍展示下拉范围内的完整明细，不随缩放裁剪，模型与速度模式筛选仍对速度表格生效。额度摘要分别显示账号权威已用、完整数据中的最新采样及当前视野截止，避免把旧视野误认为采集滞后。双击恢复下拉范围。导航最小跨度一秒，拖动约三十毫秒更新一次，抬起时提交最终位置，不新增后台轮询。空窗口保留坐标和导航能力，切换模型或收到新数据不重置已操作的窗口。未操作的快捷范围继续滚动；日期输入仍可精确指定图表初始范围与表格起止时间。

额度、TPS 和 OTel 三个数据页默认“最近 4 小时”，均提供“当天”。设置 → 常规中的当天起始时间默认本地 `00:00`；例如设为 `08:00`，早上 `06:00` 的当前监控日从昨天 `08:00` 起，到达今天 `08:00` 后进入新监控日。这只影响时间筛选，不重置账号周窗口、不删样本、不改变价格。零点默认适用于旧设置，保存后下次启动继续生效。

所有边界显示为本地时间、按双边闭区间过滤。额度按采样点时间进入回归，保留原回归算法的贡献筛选。当前余额与重置卡仍是账号实时值，不随历史分析窗口变化。时间窗不会把单个百分比区间按秒拆价；早于已保存额度样本的范围不能凭空生成额度点。

视口限制在已知采样首末边界内，超界时整体平移或限制跨度，不向最后一个采样点之后补出未来空白；速度按当前模型筛选后的有效响应确定边界。真实的内部采样间隙不会被压缩或伪造为连续采样。拟合折线在边界处插值并沿相邻段延伸，仅用于绘制，不增加训练点。若视口落在无采样的内部间隙，显示有明确标注的历史拟合参考；当前估值和贡献点仍为空，避免将参考线当成本窗口测量结果。

速度按响应完成时间先筛选，再重新分桶；纳入的一次响应保留完整 token 和耗时，不按边界截断 token。自定义窗口可以超出默认保留小时，后台自动扩大当前进程的扫描范围并补读现存日志。补读完成前显示覆盖提示；不存在或缺失边界的日志仍无法还原，实际缓存响应时间在页底显示。窗口选择只作用于本页，关闭程序后恢复默认快捷范围，不修改永久保留设置。

速度数据独立保存于 `speed.json`，包含文件游标、请求边界和输出 token 摘要，不保存对话或工具正文，也不消费额度计价游标。首次启用需要读取现有日志，后续只读新增完整行；不按文件修改时间排除仍在追加内容的旧会话。文件事件五秒去抖，六十秒补充检查；账号接口失败不影响本地采集。

- 总输出 TPS = 分组内输出 token 合计 / 响应代理耗时合计。不是各次 TPS 的算术平均。
- 可见输出 TPS 的分子为输出 token 减 reasoning token。耗时边界相同，推理期间仍计入总耗时。
- 更精确地说，设当前视野、模型和速度模式下的有效响应集合为 `A`，响应输出为 `Oᵢ`、推理输出为 `Rᵢ`、代理起止时间为 `aᵢ/bᵢ`：总输出 TPS = `ΣA Oᵢ / ΣA(bᵢ−aᵢ)`，可见输出 TPS = `ΣA(Oᵢ−Rᵢ) / ΣA(bᵢ−aᵢ)`。时间单位为秒；并行响应的耗时分别累加，不是选定四小时的墙钟时间。“可见”指非推理输出，可能含工具调用参数，不等于聊天气泡的纯文本 token。
- 请求起点由任务开始、上下文或上一响应完成建立；显式工具调用等待截至全部工具返回后才开启下一响应计时。终点为该响应最后一个模型输出记录。缺失边界、异常 token 分类不进入有效统计。
- 这些时间包含排队、预填充、推理及传输等，可能受本地日志写入时序影响，因此只能称端到端吞吐估计，不是纯解码 TPS。
- 默认每五分钟、按模型和日志明确的 Standard/Fast/unknown 分组；也可按每 N 次有效响应分组。默认最短有效时长一秒、历史二十四小时。样本数桶从保留窗口内第一条有效响应起分组，窗口滚动后可能重新分组。
- 时间桶按照 UTC 绝对时间对齐，图表与明细统一转换为本地时间，横坐标为分组结束时间。自定义边界截短的桶、未结束时间桶或未满 N 次的组标为“部分”；图中模型分色，Standard 实线、Fast 虚线、unknown 点线。
- 分组参数改变后重新聚合已保留摘要；扩大历史范围时读取仍存在的日志重新补录。缺失时间的累计计数可能包含首次扫描遇到的更早历史，不能作为当前统计窗口的缺失率。

JSONL 不提供可靠的首 token 时间戳，因此 TPS 页不推算 TTFT。1.9 起可在速度页的 **OTel · TTFT** 标签查看独立遥测。

#### 流式阶段估计 TPS（1.10.9）

独立口径为 `Σ已匹配响应输出 token / Σ(末次模型输出时间 - 首个生成 item 起始时间)`。不是服务端 TBT，也不是精确首 token 到达计量；排除 item 起点之前的等待，但仍包含客户端传输、缓冲及输出阶段停顿。思考 token 已包含在输出总数，不重复相加。

以首个 `response_item` 的 ID 关联 `item_completed.item.id`，要求生命周期跨度至少 50 ms、起点处于同一响应内；同会话 `token_usage_record.usage` 必须与 `token_count.info.last_token_usage` 的输入、缓存读、输出及思考 token 一致。错误/重试、缺逐响应证据、工具首项、思考发生在首个可见消息前、冲突或重合时序均不参与；流式时长还须达到设置中的最短响应时长（默认 1 秒）。不拿后续消息起点配此前思考 token，不用原 TPS 替代缺失。

按原有时间桶或响应数桶展示流式有效/总样本数、排除原因。流式均值及其原 TPS 对照严格使用同批合格响应；卡片和图表按视野，表格仍按下拉范围。原有效 TPS 和 OTel 的真实服务端指标独立保留。

设通过关联验证的子集为 `S`，首个可信生成 item 起点为 `sᵢ`：流式阶段估计 TPS = `ΣS Oᵢ / ΣS(bᵢ−sᵢ)`；同批有效 TPS 对照 = `ΣS Oᵢ / ΣS(bᵢ−aᵢ)`。两者都包含推理输出。这里不是从总耗时逐项精确扣除 TTFT、prefill 或网络时间；只是改变可信计时起点，仍有客户端传输、缓冲及日志时序影响。

1.10.11 起，TPS 与 OTel 常规视图隐藏免费分界后的 `codex-auto-review`：不显示对应模型选择、曲线、表格和统计贡献；原始摘要、数据库及额度依据保留。免费前的计费审批不隐藏；OTel 跨免费分界的聚合桶无法精确拆分，保守保留。普通 Luna、代码审查或来源未知的辅助请求不因名字相似而被排除。过滤只改变展示，不改变计费规则。

1.10.12 同步补齐额度表格的免费审批过滤：仅在逐响应明细完整且时间明确时，展示副本同步扣除免费审批的 token、响应数、模型名及相应层级和零倍率，金额与周额度估值不变；纯免费行不显示。底层 `QuotaSample` 和 `PricingUsages` 不删改，仍可审计及重新计价。免费前或无法确认免费边界的记录保留，不用样本结束时间猜测逐响应时间。

`speed.json` 升至版本 2，保留旧样本，后台一次性补读有近期样本或新增记录的来源，合并流式证据。没有源日志的旧样本保留并标明缺失；不清除额度历史、不改变价格或 Codex 配置。游标只保存有限的 item/响应标识、数值与时间，不保存正文。

### OTel 指标接收与保留

服务端 token 间隔仅使用 `codex.responses_api_engine_service_tbt.duration_ms`。近期没有该指标时保留空时间窗，不自动跳回旧历史；有请求但无直方图的模型仍可选。诊断区区分收到 WS timing、仅 WS 事件以及没有传输证据，计数是导出点数而非请求数。收到 `responsesapi.websocket_timing` 事件计数不等于收到服务端 TBT 数值；没有数值时，现有摘要不能区分服务器未提供还是客户端未导出，不能由客户端间隔、请求 TTFT 或 TPS 反推并冒充服务端 TBT。

- 默认只监听 `127.0.0.1:4318`，支持 `POST /v1/metrics` 的 OTLP/HTTP protobuf（包括 gzip），不支持 JSON 或 gRPC。程序不修改 Codex 配置；`otel.metrics_exporter` 需指向该端点并在实际 Codex 进程生效。端口冲突明确显示失败，不抢占已有服务。
- 白名单包含回合 TTFT、service/IAPI 两种服务端 TTFT、service token 间隔、推理耗时、回合端到端耗时、工具调用耗时。名称及语义见[官方 OTel 文档](https://learn.chatgpt.com/docs/config-file/config-advanced#observability-and-telemetry)。有配置不代表实际收到指标；只有 logs/traces 到达时不标为 TTFT 已采集。单一指标为零观测时显示不可用，不生成零延迟。
- 按模型和遥测明确提供的层级分组；缺少层级就是 `unknown`，不读取当前配置反推历史。指标数量表示直方图观测数，不是请求数或上报包数。均值为 `sum / count`，不平均各包均值；TTFT、服务端耗时与 JSONL TPS 不混算，也不参与额度计费。
- 序列以资源、作用域、完整属性及累计起始时间识别。原始属性只在内存计算用于去重的摘要，不写入数据库。首次累计包只建立基线；后续差分与样本写入同一事务。重复、乱序不重复累计；计数回退、桶边界变化或重叠 delta 明确计入不连续诊断，重新建立基线。重启接收端保留基线。
- 默认将导出区间数值摘要保留 7 天，之后合并为分钟摘要；30 天之后合并为小时摘要，最多 365 天。保留桶边界和各桶计数。图表默认按 5 分钟聚合，可按模型筛选、调整聚合分钟、输入日期或缩放拖拽。以摘要结束时间纳入整段观测；降采样摘要使用桶起点定位，边界不按比例虚构拆分，不提供逐请求或每 N 次响应重组。
- 独立存储于 `telemetry.sqlite`，默认总预算 256 MiB；数据库页硬上限为预算 49%，其余留给回滚日志和页头开销。禁用 WAL，自动回收页，单连接 SQLite 缓存约 2 MiB。定期降采样后仍接近预算时淘汰最早遥测摘要，显示累计淘汰行数；基线过多或磁盘已满则拒绝写入并报错，不删除额度历史。
- 每个请求解压后最多 2 MiB，允许 64 个轻量连接（空闲 30 秒回收），但最多同时处理 4 个指标请求，队列容量为 8；处理有超时。将连接数和大请求并发分开，避免 Desktop、IDE 等来源的长连接互相阻塞。坏包/不支持格式/超限/队列或存储失败分别返回错误，只有数值摘要提交后才确认成功。页面仅在可见时按需查询；超出 10,000 组时明确提示只显示最近结果。
- 原始 OTLP 不落盘。`/v1/traces` 直接丢弃；`/v1/logs` 只提取 `codex.sse_event` / `response.completed` 的请求 TTFT 摘要，不保存提示词、工具正文、账号或邮箱，不启用远程接收。
- “请求 TTFT（日志事件）”与旧直方图独立统计。优先采用 `event.timestamp`，否则使用非零原始 OTLP 时间，不用接收时间。事件层级优先；缺失时按会话 UUID、模型、结束时间 ±2 秒和可用输出/推理 token 数唯一关联已扫描响应。缺失和歧义保持未知，来源列区分事件直报、本地响应、未确认和多个候选。时间关联是有约束的推断，不等于请求 ID 精确关联。
- 本地速度摘要更新会触发后台重新关联；事件先到不要求重发。覆盖范围外的已确认关联不会因速度摘要自然过期而清掉。请求摘要按会话、事件时间和模型去重，冲突重传报错；旧聚合指标没有逐请求标识时不能补拆。请求摘要共享 `RetentionDays` 和磁盘预算，容量回收可淘汰旧请求。

## 生图计量边界

[OpenAI Codex 定价文档](https://developers.openai.com/codex/pricing#image-generation-usage-limits)说明生图会消耗同一 Codex included usage，消耗随质量和尺寸变化；“类似任务平均快 3–5 倍”不是可直接套用的固定价格倍率。

2026-09-07 的实际工具调用返回图片与输出提示，rollout 的 `image_gen.generation` 完成事件提供任务状态、提示词与产物路径，但没有图像 token 或可定价 usage。现有文本 `token_count` 不能证明包含独立生图费用。因此本程序当前不计入独立生图成本，诊断页会明确提示；有生图活动的百分比区间可能低估 Standard API 等价周额度。仅增加生图模型价格仍不足以精确重算，不能将未知费用视为已计量的零费用。

## Fast 与模型识别

rollout 中的 `service_tier=default/standard` 按 1×；`priority/fast` 按程序内已明确配置的 ChatGPT 额度倍率计算。当前策略包括：

- GPT-5.6、GPT-5.5 Fast：2.5×；
- GPT-5.4 Fast：2×；
- `codex-auto-review`：ChatGPT 套餐自动审批自公告后免费，不计入周额度等价金额；此前继续采用用户指定的 GPT-5.6 Luna 代理价格。普通代码审查、记忆和其他辅助请求不在免费范围，不能仅凭模型为 Luna 推断免费。
  - 程序以 [Tibo 公告](https://x.com/thsottiaux/status/2107368734981517634) 发布时间 `2026-10-06T07:13:54.094Z` 为计价分界。官方没有公布后台精确切换时刻，临界区间存在此不确定性；不追溯免计更早用量。
  - [OpenAI 帮助中心](https://help.openai.com/en/articles/11369540-using-codex-with-your-chatgpt-plan) 已明确：ChatGPT 账号登录的 Auto-review 安全检查免费、不消耗套餐用量。这不是 API-key 免费规则；本程序估算的是 ChatGPT 周额度，不是 API 账单。
  - 按逐响应时间计算基础及长上下文金额，公告后均为零，自定义价格和 Fast 倍率不会重新收费；未知速度仍标为未知，但不阻断已确认免费请求的零金额归因。
  - 免费请求的 token、原模型名和速度证据继续保留。只有免费审批、没有可计费响应的区间不能反推有效周额度。
  - `PricingUsages.Timestamp` 保存逐响应时间，便于以后离线重算。旧样本没有时间时，仅区间结束早于公告的审批可沿用旧价；跨公告或公告后的旧样本需重新读取原日志。缺失日志时保留旧记录并报告计价缺口，不按整个区间结束时间全部免计。

程序按以下顺序确定响应发生时的服务层级：

1. 优先使用 `thread_settings_applied` 或旧版 `turn_context.service_tier` 的显式层级；
2. 若整份 rollout 没有任何显式层级，且 sessions 同级 `config.toml` 顶层明确配置了 `service_tier`，并且配置最后写入时间不晚于 `session_meta` 会话创建时间，则用该配置恢复层级；
3. 无法建立上述时间证据、配置晚于会话、文件存在 Standard/Fast 混用或层级值不受支持时，继续按 `unknown` 失败关闭。

配置恢复的样本会显示为 `standard(config)` 或 `fast(config)`，不会伪装成 rollout 原生层级。这样可以恢复断网或旧客户端没有写入层级事件的区间，同时避免用当前配置反向改写更早的历史会话。

Codex `service_tier` 配置语义以 [OpenAI Configuration Reference](https://learn.chatgpt.com/docs/config-file/config-reference#configtoml) 为准；Fast 的请求值映射为 `priority`。

内置价格来源和核对日期记录在 `WeeklyQuotaMonitor.Core/PublicApiPricing.cs`；用户自定义值保存在本机 `settings.json`。修改内置价格必须同步增加业务测试。

## 回归方式

- **线性回归**：使用最近指定数量的有效样本拟合。
- **时间窗口分段**：每个时间点只使用其前方指定小时窗口。
- **高斯聚合**：按时间距离使用高斯核加权，观察稳定中心和缓慢漂移。

图表默认显示 Standard API 等价样本和回归；显式启用 `>272K` 对比后，可再选择官方长上下文样本和回归。旧价格版本样本保留为归档，但不参与当前回归。

## 请求模型关联（1.10.0）

OTel 请求 TTFT 与本地响应摘要按会话 ID、完成时刻 ±2 秒及事件提供的所有输出/推理 token 数匹配，必须只有一个候选；模型名不参与候选排除。仅时间匹配与时间加 token 匹配分别标注，关联不是服务端真实模型证明。

两端模型不同则显示模型差异并累计差异请求数，不继承本地速度；事件明确的 service_tier 仍优先。用途仅来自白名单 session_source/thread_source/turn_trigger/request_kind 的已知明确值，缺失、不支持或冲突不根据模型名称或共享会话 ID 推断。记忆提取可能复用主会话 ID，明确记忆/子代理/审查用途不强行关联本地响应。

旧请求表事务增加证据列，历史默认来源未确认。现存速度摘要覆盖区间会重算关联，覆盖外保留已存证据，不能补造已丢失的来源属性。聚合桶保留请求总数和模型差异数，混合属性显示“混合”；筛选先于聚合，图表、均值和明细口径一致。此功能不改变额度计价，不采集完整 traces 或日志正文。

## 重置判定

通常只有新 `resetsAt` 晚于旧值且采样已跨过旧重置时刻，才确认新周窗口。若百分比明确归零、新旧重置承诺相差至少一小时，并且新窗口起点接近当前观察时刻，也可确认服务端提前重置。

普通 `resetsAt` 漂移或百分比下降不足以单独证明重置。无法安全切分重置前后 token 时，区间会被丢弃而不是混算。

## 估算边界

以下情况会产生待归因或拒绝样本：

- 额度消耗来自其他设备、云任务或已删除日志；
- 本机日志尚未落盘；
- 旧窗口只有一个百分比点，或没有可验证的百分比上升；
- 模型或服务层级未知；
- 区间包含畸形完整行、文件截断或轮转；
- 百分比变化小于用户设置的最小阈值；
- 样本金额超过设置中的有效上限。

因此金额只能解释为“本机可归因活动对应的内置或用户指定 API 等价统计估计”，不能解释为订阅账单、退款价值或官方固定额度。
