# 安装、升级与故障排查

## 系统要求

- Windows 10/11 x64；
- PowerShell 7；
- Codex Desktop，或其他具有当前登录态的 `codex.exe`。

Release 中的程序为 .NET 9 自包含单文件，不需要另外安装 .NET Runtime。

## 安装

解压 GitHub Release 后，在解压目录运行：

```powershell
pwsh -ExecutionPolicy Bypass -File .\install.ps1
```

默认安装目录：

```text
%LOCALAPPDATA%\CodexWeeklyQuotaMonitor
```

安装脚本会：

1. 把新 EXE 复制为 `.installing.exe` 暂存文件；
2. 只查找可执行路径与安装目标完全相同的旧实例；
3. 停止旧实例并最多等待 15 秒；
4. 替换 EXE；
5. 保留 `settings.json`、`state.json`、历史样本和运行日志；
6. 写入当前用户的 Windows Run 自启项；
7. 启动新版本。

只更新文件而暂不启动：

```powershell
pwsh -ExecutionPolicy Bypass -File .\install.ps1 -NoStart
```

## Codex 路径

默认定位符为：

```text
codex-desktop://current
```

程序每次启动都会从当前用户 AppModel 包注册信息解析最新 Codex Desktop，并把包内 `codex.exe` 同步到数据目录的用户可执行副本。因此不会绑定 WindowsApps 中带版本号的旧路径。

不用 Codex Desktop 时，可在“设置 → 数据源”选择其他 `codex.exe`，或安装时指定：

```powershell
pwsh -ExecutionPolicy Bypass -File .\install.ps1 `
  -CodexExecutable 'C:\path\to\codex.exe'
```

Sessions 目录默认自动使用当前 Windows 用户的 `%USERPROFILE%\.codex\sessions`，迁移到其他电脑无需修改用户名路径。

## 数据文件

安装目录中主要文件：

- `settings.json`：轮询、回归、语言、主题等设置；
- `state.json`：额度基线、权威检查点、游标和历史样本；
- `runtime.log`：不含对话正文和凭据的运行状态；
- `codex-runtime\codex.exe`：当前 Codex Desktop CLI 的本地运行副本。

## 常见问题

### 托盘百分比晚于 Codex 界面

独立 App Server 的更新通知不是跨进程广播，程序仍需依赖低频轮询。可右键托盘选择“立即查询额度”，或在设置中缩短轮询间隔；最低为 10 秒。

### 百分比变化但没有金额样本

查看“诊断”和历史页顶部摘要。常见原因包括本机日志尚未落盘、活动来自其他设备、服务层级未知、模型无价格、变化低于阈值，或样本超过金额上限。

### 更新时报 EXE 被占用

确认退出托盘中的旧实例后重试。新版安装脚本会主动停止安装路径完全匹配的旧进程；若 15 秒内仍无法退出，脚本会终止，不会伪装安装成功。

### 开机没有启动

确认“设置 → 常规 → 登录 Windows 后自动启动”已勾选。自启项位于：

```text
HKCU\Software\Microsoft\Windows\CurrentVersion\Run
```

值名为 `CodexWeeklyQuotaMonitor`，路径应指向默认安装目录中的 EXE。

### 界面被缩放裁切

从 v1.3.1 起，总览卡片按实际客户区和 DPI 自动切换三列、两列或单列；空间不足时只在卡片区域显示滚动条。报告问题时请提供 Windows 缩放比例、窗口截图和“诊断”页摘要。

## 卸载

1. 从托盘右键退出；
2. 删除上述 Run 自启值；
3. 删除 `%LOCALAPPDATA%\CodexWeeklyQuotaMonitor`。

删除数据目录会同时删除设置和历史样本，请先按需备份。
